# Evidence Ledger Template

Copy this template into every deliverable that makes factual or medical
claims. The ledger is the audit trail that makes the draft defensible.

## Ledger

| # | Claim (as written) | Source (verified URL / citation) | Evidence type | Date | Population / scope | What it actually supports | Limitation | Status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 |  |  | Guideline / systematic review / RCT / cohort / manufacturer spec |  |  |  |  | Verified / Needs review / Rejected |
| 2 |  |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |  |

## Status definitions

| Status | Meaning |
| --- | --- |
| **Verified** | Source exists, is current enough, and directly supports the claim as written. |
| **Needs review** | Source is plausible but unconfirmed, indirect, outdated, or overgeneralized. |
| **Rejected** | Source does not support the claim. Remove or rewrite the claim. |

## Rules

1. One row per material claim. Split compound claims.
2. Quote the narrow conclusion the source supports, not the broad
   marketing version.
3. Record the limitation at the same time as the source; do not
   reconstruct it later.
4. If a source cannot be opened or verified, mark it `Needs review` and
   state that browsing was unavailable.
5. Never invent a DOI, URL, author, journal, or publication date.
